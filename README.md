# Bili.Dynamic.AutoDel Pro

B 站个人动态清理脚本分支，专注于删除 **已开奖的转发抽奖动态** 和 **源动态已被删除的转发动态**。

本项目 fork 自 [monSteRhhe/bilibili-dynamic-del](https://github.com/monSteRhhe/bilibili-dynamic-del)，保留原脚本的三种删除模式，并重点重做了 **删除流程、请求节奏和风控处理**。

> 当前版本：`2026.11.01`  
> 适用环境：ScriptCat（推荐）/ Tampermonkey  
> 脚本文件：[bili-dynamic-autodel.user.js](./bili-dynamic-autodel.user.js)

## 快速开始

1. 安装 ScriptCat 或 Tampermonkey。
2. [点击安装脚本](https://raw.githubusercontent.com/labmanH2/bilibili-dynamic-del-pro/main/bili-dynamic-autodel.user.js)。
3. 打开并登录 B 站，刷新页面。
4. 在脚本管理器菜单中先点 **“仅扫描（不删除）”**，确认候选数量和列表。
5. 确认无误后，再点 **“自动判断（已开奖/源已删除）”**。
6. 运行期间不要重复执行；需要中止时点进度面板上的 **“停止”**。

## 为什么会有这个分支

原脚本功能是完整的，但在动态数量较多、网络波动或 B 站风控收紧时，容易出现“删了一部分就停”或“有已开奖动态没删掉”的情况。排查后主要有以下原因：

| 现象 | 原脚本中的原因 | 本分支的处理 |
| --- | --- | --- |
| 只删了十几条就停止 | 每页动态会同时发出大量抽奖查询和删除请求，翻页也不等待请求完成；请求过于集中会触发 B 站 HTTP 412 风控 | 所有请求串行执行，并在请求之间加入随机间隔 |
| 触发风控后静默停止 | `axios` 请求没有统一的错误处理，412 或网络错误会中断翻页递归 | 识别 412/429 和常见风控码，暂停后重试；连续失败则明确报错并停止 |
| 有已开奖动态漏删 | 一边删除一边翻页，`offset` 游标会因列表缩短而跳过部分动态 | 先完整扫描所有页，再统一判断、统一删除 |
| 偶尔删除接口失败 | `getCookie(' bili_jct')` 依赖 cookie 字符串里的前导空格，可能取不到 CSRF | 重写 cookie 读取逻辑，并明确提示 CSRF 失效 |
| 短时间内多次运行后动态页空白 | 连续请求叠加风控，动态页自身的 `feed/space` 请求也被 412 拦截 | 默认 10 分钟运行冷却、运行锁，并支持手动停止 |
| 删除 X 天前输入数字反而报错 | 输入校验条件写反了 | 已修正为非负整数校验 |

需要说明的是：**单次运行的旧脚本就已经可能触发风控**，多次运行只是进一步叠加。B 站返回 412 时通常是一个验证码/风控页面；动态页拿不到数据，就会表现为“个人动态不显示”，这不是动态被删光，也不是账号被封，风控解除后会恢复。

## 现在的功能

- **自动判断**：删除源动态已删除的转发动态，以及源动态为“互动抽奖”且已经开奖的转发动态。
- **指定用户**：按源动态作者的用户名或 UID 删除转发动态，支持英文逗号分隔多个目标。
- **删除 X 天前**：删除源动态发布时间早于指定天数的转发动态，并跳过未开奖的抽奖动态。
- **仅扫描**：只扫描和判断，不发送任何删除请求，适合首次使用或复核。
- **取关功能**：可选；删除成功后把对应 UP 主加入取关队列，任务结束时统一取关。
- **进度面板**：显示扫描页码、已扫描数量、命中数量、删除数量、失败数量、耗时和最近日志。
- **停止任务**：面板和菜单都可以停止，当前请求结束后安全退出。
- **运行冷却**：默认两次运行间隔 10 分钟，避免连续操作叠加风控。
- **运行锁**：防止同一时间重复启动任务；异常退出后可手动清除。
- **风控退避**：遇到 412/429 或 `-352/-412/-509/-799` 时自动暂停，最多重试两次，仍失败则停止并提示。
- **抽奖查询缓存**：同一个源动态只查询一次抽奖状态，减少重复请求。
- **可调请求间隔**：读取和删除分别设置最小/最大延迟。

## 工作流程

脚本把一次任务拆成三个阶段，避免“边删边翻页”带来的漏删：

1. **扫描阶段**：只读请求动态列表，按 `offset` 翻完所有页，按动态 ID 去重并保存。默认最多 500 页作为安全上限。
2. **判断阶段**：逐条检查转发动态。自动模式会判断源动态是否已删除，或查询互动抽奖状态是否为已开奖；同一个源动态只查询一次。
3. **删除阶段**：从旧到新逐条串行删除。每条删除之间使用独立的随机延迟；遇到风控会暂停重试，连续失败则停止整个任务。

删除完成后，如果开启了取关功能，再按取关队列逐个处理。取关失败的 UID 会保留在队列中，方便下次继续。

## 安装

### ScriptCat（推荐）

1. 安装 [ScriptCat](https://scriptcat.org/) 扩展。
2. 打开 [脚本安装链接](https://raw.githubusercontent.com/labmanH2/bilibili-dynamic-del-pro/main/bili-dynamic-autodel.user.js)。
3. 确认安装并保存。
4. 打开 B 站页面，刷新后即可在扩展菜单中看到命令。

### Tampermonkey

同样支持。安装脚本后刷新 B 站页面即可。脚本通过 `@require` 加载固定版本的 axios；如果加载失败，脚本会提示检查网络或脚本管理器的依赖加载状态。

## 使用说明

在 B 站页面点击脚本管理器图标，可以看到以下菜单：

| 菜单 | 作用 |
| --- | --- |
| 自动判断（已开奖/源已删除） | 删除已开奖的互动抽奖转发，以及源动态已删除的转发 |
| 指定用户 | 输入源动态作者的用户名或 UID，删除对应转发 |
| 删除 X 天前 | 输入天数，删除源动态发布时间早于该时间的转发 |
| 仅扫描（不删除） | 只输出候选，不执行删除 |
| 停止当前任务 | 请求停止当前任务 |
| 显示进度面板 | 重新显示被隐藏的进度面板 |
| 打开设置 | 修改延迟、取关、通知等设置 |
| 清除运行锁/冷却 | 仅在任务异常退出、无法再次启动时使用 |

### 建议的使用顺序

1. 先执行 **“仅扫描（不删除）”**，观察扫描页数、命中数量和预计耗时。
2. 确认候选符合预期后，再执行 **“自动判断”**。
3. 扫描阶段可能比较久，尤其是转发数量多、动态总数大的账号；这是为了降低风控概率。
4. 运行期间不要重复点菜单，也不要在另一个标签页同时运行。
5. 如果中途停止，已删除的动态不会恢复；下次运行会重新扫描剩余动态。

## 设置项

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用取关功能 | 关 | 删除成功后取关对应 UP 主 |
| 显示进度面板 | 开 | 任务运行时显示右下角面板 |
| 弹出系统通知 | 关 | 通过脚本管理器发送完成/错误通知 |
| 读取间隔最小值 | 1000 ms | 动态列表、抽奖查询等只读请求的最小间隔 |
| 读取间隔最大值 | 2000 ms | 只读请求的最大间隔 |
| 删除间隔最小值 | 2500 ms | 删除请求的最小间隔 |
| 删除间隔最大值 | 4000 ms | 删除请求的最大间隔 |
| 两次运行冷却 | 10 分钟 | 防止短时间反复运行 |

默认值偏保守。把间隔调低会更快，但触发风控的概率也会上升；不建议把读取间隔降到 800ms 以下、删除间隔降到 1500ms 以下。

## 风控说明

B 站对动态相关接口有频率限制。触发时常见的表现是：

- 接口返回 **HTTP 412**，内容是一个验证码/风控页面；
- 脚本日志出现 `-352`、`-412`、`-509`、`-799` 等返回码；
- 个人动态页或动态列表暂时空白、加载不出来。

处理建议：

1. 立即停止任务，不要连续重试。
2. 等待 30–60 分钟；如果页面出现验证码，先完成验证。
3. 期间不要反复刷新动态页，也不要在多个标签页同时运行脚本。
4. 恢复后先用“仅扫描”确认接口正常，再执行删除。

脚本自身会暂停并重试，但**不能保证一定绕过风控**。如果连续触发，脚本会选择停止，而不是继续加频请求。

## 常见问题

### 提示“未检测到登录状态”

确认已经登录 B 站，并刷新页面。脚本需要读取 `DedeUserID` 和 `bili_jct` 两个 cookie。

### 提示“CSRF 校验失败”

通常是 `bili_jct` 已过期。刷新 B 站页面或重新登录后再试。

### 提示“axios 依赖加载失败”

脚本通过 unpkg 加载 axios。检查网络是否能访问 `unpkg.com`，或稍后重试。

### 任务看起来很久没有删除

脚本会先扫描完所有页，再开始删除。扫描阶段只发只读请求，进度面板会显示当前页码和已扫描数量；这不是卡死。

### 运行锁没有释放

正常情况下任务结束会自动释放。如果浏览器崩溃或页面被强制关闭，可以在菜单中执行 **“清除运行锁/冷却”**，再重新运行。

### 动态页还是不显示

先确认是否触发了 412 风控。等待并完成验证码后再看；如果长时间不恢复，可以退出登录再重新登录，或换网络环境尝试。

## 适用范围与限制

- 只处理 **转发动态**，不会删除自己发布的原创动态。
- “互动抽奖”判断沿用 B 站 `lottery_notice` 接口的 `business_type=4`，并以 `status == 2` 作为已开奖条件；其他类型的活动可能不在覆盖范围内。
- 源动态已删除的转发会直接删除，不要求它一定是抽奖动态。
- B 站接口、字段或风控策略变化可能导致脚本失效，需要后续维护。
- 批量删除不可撤销。首次使用请先“仅扫描”，确认候选列表后再执行。
- 本项目没有使用你的账号做真实删除测试；逻辑验证使用的是模拟动态和模拟接口返回。

## 验证情况

开发时用模拟数据验证了以下场景：

- 3 页、12 条动态，7 条候选全部删除，且确认所有动态页扫描完成后才开始删除；
- 模拟首次请求 412，脚本暂停后重试成功；
- 模拟持续 412，脚本重试 3 次后停止，0 条误删，运行锁正常释放。

这些测试只能验证脚本流程，不能替代真实账号上的小规模验证。建议先“仅扫描”，再小批量执行。
